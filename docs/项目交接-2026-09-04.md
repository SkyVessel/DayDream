## 产品与交互基线

除非用户明确要求，不要改变字体、主题、内容布局或现有间距。最近一次 UI 要求只允许更换图标，因此当前图标已经统一为 SF Symbols，布局、字体和颜色应保持现状。

当前关键交互：

- `⌘N`：新建笔记，选中新笔记、打开并进入重命名。
- `⌘O`：打开/关闭侧栏。打开后焦点进入侧栏；再次按下会关闭侧栏并回到编辑器。
- 侧栏获得焦点时，`↑`/`↓` 移动选中项；经过笔记时，右侧编辑器实时预览该笔记，但键盘焦点仍留在侧栏。
- 侧栏中对笔记按 Enter：确认选择、关闭侧栏并把焦点交给编辑器。
- 侧栏中对文件夹按 Enter：展开或折叠文件夹。
- 侧栏焦点下按 Escape：退出侧栏导航并回到编辑器。
- 侧栏焦点下按 `⌘Backspace`：只允许删除笔记，先弹出二次确认；Escape 取消，Enter 确认。删除通过 Finder 废纸篓完成，可恢复。
- 编辑器焦点下的 `⌘Backspace` 仍是“删除到行首/段首”，不会触发侧栏删除。
- `⌘+` / `⌘-`：改变编辑画面缩放。
- 选中文字后可用快捷键应用粗体、斜体、高亮、文字颜色和行内代码；设置页可重录所有应用快捷键，冲突时会交换绑定，并可恢复默认。
- 文件夹展开箭头已有扩大后的点击区域，视觉位置不应随意改变。

## 当前已实现功能

### 编辑器

- 自定义不闪烁、带缓动的粉色插入光标。
- 内容宽度、行距、空格宽度、字体、语言和外观设置实时生效并持久化。
- 可导入 TTF、OTF、TTC 字体；字体复制到应用支持目录并在进程内注册。
- 四级标题、无序列表、有序列表、Todo、引用和围栏代码块。
- 粗体、斜体、行内代码、链接、图片、文字颜色、高亮。
- 高亮使用自定义圆角绘制；相邻片段可合并，取消样式时会清理系统或临时下划线，避免残留淡粉色线。
- 空标题用淡色 `Heading 1` 至 `Heading 4` 占位，不写入文件。
- 列表序号是根据连续列表和缩进动态生成的；Todo 每行有独立状态，可单独点击。
- Tab/Shift-Tab 调整列表缩进；若存在单词补全候选，Tab 优先接受候选。

### Markdown 输入

在段落开头输入下列标记并按空格，会隐藏语法标记并应用块样式：

- `#`、`##`、`###`、`####`
- `-`、`*`
- `1.`
- `[ ]`、`[]`、`[x]`、`[X]`
- `>`
- 三个反引号

在空段落输入 `/` 会显示命令面板，支持上下选择、Enter 确认、Escape 关闭和鼠标点击。存在输入法 marked text 时不接管相关按键。

### 工作区与侧栏

- 默认资料库位于 `~/Library/Application Support/DayDream/Library`。
- 侧栏映射真实文件夹和 `.md` 文件，文件夹优先、按名称排序。
- 支持新建、行内重命名、复制、粘贴、拖拽移动、移到废纸篓。
- 点击“笔记库/Library”可选择外部文件夹作为资料库。
- 曾选择多个资料库时显示左右切换箭头，选择记录持久化。
- 侧栏头部有导入按钮、为浮动侧栏开关保留的 30pt 空位、以及新增按钮。
- 非全屏时侧栏开关位于红绿灯右侧；全屏时自然向左上移动。侧栏展开/收起有位置动画。
- 旧的标签页与左右分屏已按用户要求移除，当前是单文档编辑器。

### 导入、导出与写作工具

- 侧栏导入支持 `.md` 和 `.docx`，导入后在当前资料库中生成新的 `.md` 笔记。
- 右上角导出按钮支持 Markdown 和 Word。
- 导出按钮右侧的三点按钮使用 Button + popover 实现。之前用 SwiftUI `Menu` 时宿主视图缩成约 6×14，导致 32×32 标签被裁切；不要恢复为原来的 Menu 写法。
- 三点菜单包含 Focus Mode、文字颜色、荧光笔颜色、单词自动补全、自动拼写修正。
- Word 导入/导出依赖 AppKit 的 Office Open XML 支持，不依赖 Pandoc。复杂页面布局、浮动文本框、修订元数据等会被扁平化为可读内容。
- 单词补全由 `NSSpellChecker` 提供，候选后缀只绘制为淡色临时文字；按 Tab 后才真正进入文档、撤销栈和保存内容。
- 自动拼写修正使用 AppKit 系统能力；代码块内尽量禁用。

## Focus Mode 的当前语义

当前实现并不是简单地按 `。！？.!?` 拆分。

`FocusSentenceResolver` 先截取光标所在段落，然后使用 `NLTokenizer(unit: .sentence)` 找出光标所在的自然语言句子；找不到完整句子时回退到整个当前段落。编辑器通过 TextKit 临时前景色让其他内容变淡，不会修改或保存 Markdown。

用户最近明确表达过对 Focus Mode 的理解是“通过句号分割”。这与当前 NLP 分句语义可能不一致，是下一位接手者需要优先确认或调整的产品点。若直接修改，建议只替换 `FocusSentenceResolver` 并补中英文标点、段尾未完成句和光标位于标点边界时的测试，不要改 Focus Mode 的临时绘制层。

## Markdown 是否是真 Markdown

是。编辑区显示的是去掉标记后的富文本视图，但保存和导出的内容是实际 `.md` 文本：

1. `MarkdownDocumentCodec` 把源文件解析为块模型。
2. `MarkdownTextStorage` 把块与行内语义映射为 `NSAttributedString` 属性。
3. 用户编辑时操作可见文字和语义属性。
4. 导出时重新序列化为 Markdown，再由 `SourcePreservingMarkdown` 合并未修改的原始行。

标准 Markdown 部分可被常见编辑器解析：标题、列表、任务列表、引用、围栏代码、粗体、斜体、行内代码和链接。文字颜色与荧光笔没有统一的 CommonMark 表达，因此使用 HTML `<span style="...">` 扩展；不支持 HTML 的 Markdown 阅读器会把它当 HTML 或忽略样式。

## “无损”保存的真实边界

当前无损策略是“未修改原文优先”，不是完整的任意 Markdown AST 无损编辑器：

- 文档打开后完全不改，导出结果与原始字符串完全一致。
- 修改一行时，与加载基准仍相同的其他行会写回原始内容。
- 插入或删除行后，通过行差异继续匹配后续未修改行。
- CRLF 文档的行尾风格会尽量保留。
- 原始列表符号、序号、Todo 大小写、空白、HTML 和未知语法只要所在行未改变，就不会被规范化。
- 真正编辑过的行会使用 DayDream 的规范形式输出；如果该行包含当前模型不理解的复杂语法，编辑它仍可能丢失那部分结构。
- 当原始行数和初始规范化基准无法一一对应时，会退化为规范化输出并保留首选换行格式。

相关测试在 `SourcePreservingMarkdownTests.swift` 和 Markdown/InlineMarkdown 测试中。继续扩展语法时应坚持“未知即保留”，不要把一次打开保存变成整篇重写。

## 关键数据流

打开与保存：

```text
SidebarView 选择 URL
  → WorkspaceView 调用 DocumentController.open
  → EditorView.load
  → MarkdownDocumentCodec.parse
  → MarkdownTextStorage.attributedString
  → DayDreamTextView 编辑
  → exportMarkdown + SourcePreservingMarkdown.merge
  → DocumentController 350ms 防抖原子写盘
```

`DayDreamTextView` 自身还对 Markdown 变化做约 75ms 的通知防抖。切换笔记、修改文件结构、退出应用前会显式 flush。`DocumentController` 保存前比较磁盘内容；若其他应用已修改同一文件，会暂停覆盖并让用户选择载入磁盘版本或保留 DayDream 版本。文件已经删除时不会被延迟保存“幽灵重建”。

## 当前风险与待确认事项

1. **Focus Mode 语义不一致**：实现用 `NLTokenizer`，用户理解为按句号类标点切分。下一步优先处理这个产品差异。
2. **性能优化被暂停**：用户曾反馈快速输入卡顿，代码中已有局部可视区域绘制、75ms 通知防抖、Focus 范围缓存和性能诊断测试，但用户随后明确要求先停止性能工作。没有新指示前不要继续扩展优化。
3. **全量测试偶发崩溃**：signal 11 尚未定位。优先单独运行 `PerformanceDiagnosticsTests`，再判断是测试生命周期还是产品代码问题。
4. **工作区规模大且未提交**：不要做大范围重构、格式化或“顺手清理”。每个补丁只触及当前需求相关文件。
5. **Word 转换存在天然边界**：复杂 Word 排版会扁平化，不应承诺像素级或结构级完全还原。
6. **无损是按行保留**：不等于编辑任意未知语法后仍能还原；扩展时需补真实往返测试。
