## 1. 空格宽度不持久：只对当前画面生效，新输入的空格是默认宽度

**现象**
- 设置页调「空格宽度」后，已有文字的空格变宽了，但**之后再输入的空格回到默认宽度**。
- 用户体感「不持久保存」。

**根因分析**
- 加宽机制：`DayDreamTextView.applySpaceWidth(in:)` 给空格字符加额外 `.kern`，调用点为 `applyTheme()`（全量）、`load()`（全量）、`didChangeText()`（编辑段落）。
- 疑点 A：`didChangeText` 里用 `textStorage.editedRange` 定位编辑段落，`editedRange` 的时机/取值在某些输入路径下可能已失效（防护代码静默跳过），导致新打字的空格没有补宽。
- 疑点 B：新输入字符带的是 `typingAttributes`（只有基础 kern），依赖 `didChangeText` 事后补宽——补宽时机不可靠。
- 疑点 C（待验证）：`UserDefaults` 持久化是否真生效。手打包的 `.app`（bundle id `com.daydream.editor`）与 `swift run` 的 defaults domain 不同，测试时可能跨域看错。

**修复方案**
- 放弃「事后补宽」的脆弱时机，改为在文本存储层统一处理：覆写/挂钩 `NSTextStorage.processEditing`（或 `delegate textStorage(_:didProcessEditing:)`），对 `editedRange` 所在段落稳定补宽。
- 验证重启后设置仍在（同一 bundle id 下测）；若跨域问题存在，统一运行方式。

## 2. 高亮视觉：高度/宽度与文字不匹配 + 需要圆角 + 相邻自动连接

**现象**
- 高亮（`.backgroundColor` 属性）按属性 run 逐段绘制：整行高、直角、相邻高亮段之间断开、与文字高度不匹配。

**期望**
- 高亮块高度 = 光标高度（字体 ascender − descender），圆角。
- **自动连接**：相邻（同行内连续或被空格隔开但同属一个高亮语义）的高亮段合并成一个连续圆角块。

**修复方案**
- 不再依赖 `.backgroundColor` 系统绘制。在 `DayDreamTextView.draw(_:)` 里：
  1. 枚举 `.dayDreamHighlight` 语义键的 run，用 layoutManager 取每段 glyph 的 bounding rect；
  2. 按 y（行）分组，同行相邻段（间隙小于阈值或仅隔空格）合并；
  3. 高度收敛到光标等高（参考 `currentCaretRect()` 的计算：baseline − ascender，高 ascender − descender），画圆角矩形填充 `DayDreamTheme.inlineHighlightColor(...)`。
- 语义键与序列化（`<span style="background-color:...">`）保持不变，只换绘制层。
- 参考：光标高度计算在 `DayDreamTextView.currentCaretRect()`；装饰绘制先例在 `drawBlockDecorations`。

## 3. 选中文字点高亮后，再次点击无法取消高亮

**现象**
- 选中文字 → 悬浮工具条点「高亮」→ 高亮生效；**再点一次无法 toggle 取消**。

**根因分析**
- `toggleInlineValue(.dayDreamHighlight, value:)` 依赖读取 `selectedRange.location` 处的语义键判断是否已高亮——但第一次点击后：
  - 疑点 A：`afterInlineStyleChange → rebuildAttributes` 改属性会触发 `didChangeText`，而 `didChangeText` 里有 `hideFormatPanel()`——**工具条点一下就消失了**，根本点不到第二次。
  - 疑点 B：即使面板还在，`selectedRange.location` 处属性读取/比较可能有边界问题。

**修复方案**
- `didChangeText` 只在**字符内容**变化时隐藏面板（判断 `textStorage.editedMask` 是否含 `.editedCharacters`），纯属性编辑不隐藏。
- 工具条动作执行后保持/重显面板（选区未变时重新 `showFormatPanel()`）。
- toggle 判定改为「选区是否整体都被该高亮值覆盖」而非只看起点。

## 4. 移除标签页（tabs）与分屏（split）两个功能

**要删的**
- `EditorPaneStore.swift`（标签页模型）、`TabStripView.swift`（标签条 UI）。
- `WorkspaceCoordinator` 中：`isSplit` / `focusedPane` / `textViews` / `unsplit` / `mergeTabs` 调用、⌘D、⌘⌥←/→、⌘1-9、⌘W 的标签页逻辑。
- `DayDreamCommands`（DayDreamApp.swift）中：⌘D、⌘⌥←/→、⌘1-9 菜单项；⌘W 恢复为单纯关窗口（或保留 CommandGroup(replacing: .newItem) 但只剩 ⌘N）。
- `WorkspaceView` 双窗格布局（`paneView`、分屏 Divider）。
- `SettingsView` 快捷键列表中对应行（⌘1…9、⌘D、⌘⌥←/→）。
- `Tests/DayDreamTests/EditorPaneStoreTests.swift`。

**要保留/回归的**
- ⌘N 新建笔记：创建后直接在当前（唯一）编辑器打开，进重命名。
- ⌘O 侧栏导航、⌘R/⌘C/⌘V 侧栏焦点操作（**注意**：`EditorView.onBecameFirstResponder` 用于退出侧栏焦点的机制要保留）。
- 文档内容模型：回到单文档 controller（可新建一个精简的 `DocumentController`：当前 URL + markdown + 防抖落盘 + flush；复用 `EditorPaneStore` 中 flush 的「文件不存在不写盘」防幽灵重建逻辑）。
- 结构变更同步（重命名/移动/删除后更新当前打开的 URL；删除时清空编辑器）。
- `WorkspaceStore` 现状（树 + 选中 + 多库 + beforeMutation + pasteItem）不动。
