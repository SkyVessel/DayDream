# Vibero 标注机制研究：供 DayDream 后续 AI 功能使用

研究日期：2026-09-09。此次仅阅读代码，没有运行 Vibero，也没有把它的代码复制进 DayDream。

## 范围与版本

用户所称的 videro 对应此前提供的 [Vibero 仓库](https://github.com/chenyu-xjtu/Vibero)。本次检出的主仓库提交为 `d458d293606168f1d38d7884276b415567a29e6d`。它的 `reader` 是 Zotero reader 子模块，锁定提交为 `8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa`，不是主仓库下的一份独立 AI 旁注实现。

依据：[子模块配置](https://github.com/chenyu-xjtu/Vibero/blob/d458d293606168f1d38d7884276b415567a29e6d/.gitmodules)、[锁定的 reader](https://github.com/chenyu-xjtu/Vibero/tree/d458d293606168f1d38d7884276b415567a29e6d/reader)。README 将段落摘要列为计划项；不能据此声称它已经实现了“全文 AI 旁注”。下文讨论实际存在的阅读器标注及其可借鉴部分。

## 1. 数据与格式如何处理

原文摘录 `annotation.text` 与用户评论 `annotation.comment` 分开保存；标注还有独立的 ID、类型、颜色、页面位置、标签和修改时间。页面高亮与评论显示共用该标注 ID，不依靠“拿评论去全文搜索”建立联系。侧栏的 `SidebarPreview` 分别渲染摘录和评论，允许分别展开、编辑；只读权限也独立传递。

标注的富文本编辑器支持有限的格式：粗体、斜体、上标、下标。它把允许的文本标记转换为编辑 DOM，保存时再转换回来；清理过程把 `strong` 归一为 `b`，剥离不允许的元素与属性，同时保留换行结构。这不是任意 HTML 渲染器，也不等于 AI 聊天页面的 Markdown 渲染器。

依据：[preview.js](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/components/common/preview.js#L229)、[editor.js](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/components/common/editor.js#L4)。

## 2. 字号、大小和换行

侧栏标注采用统一界面字号：编辑器样式为 `rem(12)`，行高为 `4/3`，文本可自动折行；阅读器的界面字号设置通过根元素字号缩放传递。它没有在这些侧栏组件中逐句读取 PDF 原文的字体，再把旁注设置为相同字号。引用区域左侧的颜色条与文本内容分层绘制，文本留出固定内边距。

需要区分两种尺寸：侧栏卡片的文字尺寸属于 UI；直接写在 PDF 页面上的 text annotation 则有自己的 `position.fontSize`，绘制代码使用该字号和页面坐标。这两种机制不能混为一谈。

依据：[_editor.scss](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/stylesheets/components/_editor.scss#L1)、[根字号更新](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/reader.js#L612)、[页面文字标注](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/pdf/lib/render.js#L169)、[引用颜色条](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/stylesheets/components/_preview.scss#L70)。

## 3. 如何高亮对应的原文

PDF 标注保存页面索引及一组原文矩形，跨页时还可带下一页矩形。渲染前把文档坐标转换为当前页面视图坐标，再按各个矩形绘制。多行文本因此可以逐行高亮，而不是把整段的外接大矩形全部涂色。缩放后重新换算坐标，不把上一次屏幕像素位置当作永久锚点。

中央阅读器维护选中的标注 ID，并同时传给主、次阅读视图。选择侧栏标注可通过 ID 导航到对应位置；页面选择变化也更新侧栏。选中状态、高亮位置和评论编辑状态是相关但不同的数据。

依据：[PDF 坐标与高亮绘制](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/pdf/lib/render.js#L47)、[选择同步](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/reader.js#L454)、[PDF 选择更新](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/pdf/pdf-view.js#L1010)、[侧栏到页面的导航](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/reader.js#L1390)。

这说明可以借鉴独立的定位与覆盖层；不应把整张 PDF 截图、反色或模糊作为旁注高亮方案。后一点是 DayDream 的设计结论，并非声称 Vibero 所有渲染路径都不处理主题颜色。

## 4. 展开和收起的真实行为

`annotations-view.js` 明确维护四个状态：

| 状态 | 行为 |
| --- | --- |
| 0 | 无选中或多选，摘录和评论保持折叠 |
| 1 | 单选标注，展开评论 |
| 2 | 同时展开评论和原文摘录 |
| 3 | 摘录展开并可编辑 |

选中集合改变时，单选进入状态 1，其余进入状态 0；点击已选中的原文区域可以改变展开状态。双击进入摘录编辑还检查选中后经过的时间，以免刚选中就误触编辑。键盘、焦点及拖拽也参与状态管理。

折叠由 CSS 的三行截断完成；展开取消截断并恢复普通块级布局。选中的卡片会平滑滚动到附近可见区域。本次检查的实现不是“悬停自动展开、尾部渐隐、其他卡片模糊”的交互。后者若用于 DayDream，应作为自己的设计进行验证，不能当作已从 Vibero 验证的行为。

依据：[状态定义及更新](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/components/sidebar/annotations-view.js#L114)、[点击与双击](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/components/sidebar/annotations-view.js#L300)、[三行截断](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/stylesheets/components/_editor.scss#L93)。

## 5. 刷新与持久化

AnnotationManager 以 ID 管理增删改、排序和撤销历史。更新时调用渲染回调；待保存项另存于集合，再交给保存回调。更新数据不必等磁盘写入才反馈到界面。位置变化会同时维护排序信息，修改时间也由管理层更新。

依据：[annotation-manager.js](https://github.com/zotero/reader/blob/8dc837d2380c3fbdde59c235d0c2cf47ff3bb2fa/src/common/annotation-manager.js#L20)。

## 6. DayDream 后续 AI 标注建议（尚未实现）

1. **独立数据。** AI 结果不要直接混入笔记正文。每条标注具有 ID、来源文档标识、原文片段、锚点、结果、状态和时间。删除旁注仅删除该记录，支持删除单条和全部清除。
2. **稳定锚点。** Markdown 使用段落标识及文本范围，并保留上下文校验；编辑后更新锚点或显示“来源已变更”。PDF 保存页码和逐行矩形，用 PDFKit 转换到显示坐标，不保存屏幕位置。
3. **限制展示格式。** 从小范围 Markdown 样式开始，先支持粗斜体、段落和列表。原文摘录与 AI 结果分区，字号由界面设置统一控制，不盲目跟随 PDF 中标题或脚注的字号。
4. **明确交互。** 默认折叠到三行；点击展开，Esc 收起，删除始终可达。悬停只做原文定位反馈，不触发生成，不改变正文，不把 PDF 或其他文本模糊化。
5. **可取消且不回流。** 每次请求记录文档及标注版本；清除标注、切换文档或取消请求后，迟到的结果不得重新创建旧旁注。当前删除操作必须立即更新 UI，再持久化。
6. **统一选择状态。** 主窗格和参考窗格共用标注选中 ID；只有活动窗格接受键盘输入。展开布局测量不能从 draw 中递归触发，滚动只处理可见标注。
7. **测试重点。** 跨页、多列 PDF、缩放、长段落、混合字号、中文、重复原文、重命名、正文编辑后的锚点、关闭窗口时的请求回调、删除后重启不复现。

## 当前版本决定

本轮 DayDream 暂停全部翻译入口、任务运行和旁注展示。经用户追加授权，已清理原来的旁注翻译记录：33 条，分布在 2 个独立 JSON 文件中；未删除笔记，也未改写笔记正文。旧 `!!` 文档块只保留读写兼容，不执行翻译。未来 AI 功能应按上面的数据与状态边界重新实现，而不是恢复旧旁注代码。
