# 导出系统调整 · 2026-09-10

## PDF

- 使用离屏 DayDreamTextView、MarkdownTextStorage、TextKit 排版，复用圆角高光和列表/引用装饰绘制。
- 从当前编辑器取得栏宽、缩放和已载入的图片/视频封面；重建媒体排除区域，保持文字避让。
- 使用当前导出外观对应的编辑器背景和文字颜色。正文直接写入 PDF 图形上下文，文字可选择；不会把整页转换为截图。
- 页宽跟随编辑器窗口宽度，页高为页宽的 √2 倍。分页尽量不切断文字行或单页能容纳的图片。超过一页高的图片分段显示。
- 不导出选区、光标、自动补全、工具条、Focus/Retype 临时淡化和 Ultra Focus 的滚动留白；不改变原编辑器状态。
- 网络封面复用已显示内容；不会为了导出重新联网或等待网络素材下载。

## Word

- 写出原生 DOCX，图片作为 PNG 嵌入包内，使用 DrawingML 页面定位，文件移动后仍能显示图片。
- 保留 TextKit 已计算的视觉行、水平位置和行距；多段文字通过制表位绕过图片。图片使用 wrapNone，避免 Word 再次自动环绕造成双重偏移。
- 正文仍可编辑，但为布局保真使用显式分行。修改大量文字或移动 Word 中的图片后，需要用户重新调整排版；不等于 DayDream 的实时拖动避让。
- 白色页面，不套深色背景；保留基本字体、颜色、粗斜体、下划线、删除线和高光。Word 无原生等价的圆角高光，使用普通文字底色。
- 系统内部字体名在 Word 中回退为 Helvetica Neue；其他字体写入其家族名称。目标电脑缺少字体时，Word 会替换字体，可能改变排版。
- AppKit 的 DOCX 读取器会丢失链接和标题级别，针对本导出器生成的未压缩 ZIP，通过标准 XML 元数据恢复。只在导入的实际段落文字完全匹配时应用，避免导入陈旧内容。
- ZIP 在进程内生成，无外部命令依赖。测试用系统 unzip 验证包完整性。

## Markdown

保留原始 Markdown 和 DayDream 媒体元数据，导出时复制旁边的 `.daydream-assets` 资源。修复 `.markdown` 扩展名未复制资源的问题。其他 Markdown 阅读器不一定支持 DayDream 的图片位置、背景及扩展样式；需要视觉一致时使用 PDF。

## 用户验收清单

1. 在浅色、深色各导出一份 PDF，对比背景、字号、文字颜色和圆角高光；放大后确认正文清晰、可选择。
2. 在左侧、中间、右侧放置不同大小的图片，输入足够长的文字，比较 PDF 和 Word 的图文位置。
3. 用跨多页笔记测试页尾图片、列表、引用、最后一行；确认内容没有遗漏。
4. 导出 Word 后用 Microsoft Word 打开，确认图片能显示、文字可编辑、标题和链接正常。
5. 将导出的 Markdown 连同 `.daydream-assets` 文件夹移到另一处，再用 DayDream 打开。
6. 在 Focus、Ultra Focus 或有选中文字时导出，确认原笔记、选区与滚动状态不变。

未使用 computer use。视觉验收由用户完成，不自动推送或发布。

参考：[Microsoft DrawingML Anchor](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.wordprocessing.anchor)
